## Ground rules for this session

From `AGENTS.md` and `rylee.md`, the ones that bite hardest here:

1. **The gate is the whole gate.** `uv run --group test ruff check src tests && uv run --group test pytest -q` must be green before you claim any PR is done. Paste the output with the claim.

9. **Branch per PR**, `feat/*` or `fix/*` off `main`, PR via `tea --repo rylee/vefr`. Do not push to `main` directly. Do not merge without Rylee saying so.

### PR-A `fix/scaffold-nameerror` - Phase 0

Fixes: **H1**.

`src/vefr/cli.py:1217-1221` binds `sha` only inside
`if root.returncode == 0:`, then reads `sha.returncode`
unconditionally on the next line. Any non-git checkout - a container,
a tarball install, a permissions failure on `__file__`'s parent -
raises `NameError: name 'sha' is not defined` inside
`ratatoskr ferry scaffold`, which is a documented command.

`ruff --select F821` does **not** catch this (verified: `exit=0`),
because the name is bound in a branch. A test is the only guard.

Edits:

| File | Change |
| --- | --- |
| `src/vefr/cli.py:1211-1222` | Restructure so `engine_sha` resolution cannot read an unbound name. Fold the two `if`s into one, or bind `sha = None` first and guard on it. Keep the `engine_sha = 'unknown'` fallback behavior identical. |
| `tests/test_scaffold.py` | New case: monkeypatch `subprocess.run` so the `git rev-parse --show-toplevel` call returns non-zero, then assert `cmd_scaffold` completes and the scaffold records `engine_sha` as `unknown` rather than raising. |

### PR-E `feat/neutrality-shape-guard` - Phase 2

Fixes: **H4**. This is the only PR in the plan that prevents a
*class* of bug rather than an instance, and it is why the strip kept
coming back.

`tests/test_pack_neutrality.py` is a **denylist**. It reads
`tests/canon-strings.local.txt` (gitignored, 20 literal terms) and
fails on any hit. It cannot catch `web/town.js:302` because
`she is there` was never on anyone's list. Five agents each "fixed"
the strip and the guard reported green every time.

Add a second, **shape-based** check to the same test module that does
not need to know any names.

The rule: no third-person singular gendered pronoun
(`she`/`her`/`hers`/`his`/`him`) in a user-facing string literal
under `web/` or `src/vefr/`.

Measured surface at `d034f81`, before PR-D lands:

```
web/town.js:302,335,341          3 hits  -> fixed by PR-D
src/vefr/journey.py:59,74,75,81  4 hits  -> fixed by PR-D
src/vefr/runes.py:122            1 hit   -> fixed by PR-D
web/index.html:1412              1 hit   -> fixed by PR-D (comment)
src/vefr/saga.py:4,12            2 hits  -> legitimate, must be exempted by shape
```

So after PR-D the guard should find only the two `saga.py` docstring
lines. Design the check so those two do not need an allowlist entry -
scope it to string literals and comments in code, not module
docstrings, or scope it to `web/` plus non-docstring `src/` strings.
An allowlist is a permanent blind spot; that is the whole lesson of
this finding.

Requirements:

- Land as a **hard assert** (decided). No warn phase.
- The failure message must name the file, line, and matched pronoun,
  and must say plainly that the string leaves the source.
- Keep the existing literal-term test intact and passing. This is a
  second test function in the same module, not a replacement.
- Document the guard's reasoning in the module docstring the way the
  existing one does - a future agent needs to know why an allowlist
  was refused.

Also fix, in this PR: add a gate assertion that the rename cannot
regress.

```bash
rg -i "<the old names>" src/ web/ --glob '!vendor/**'    # must return nothing
```

Express that as a test so it runs in the gate. Without it, PR-F's
work rots in three weeks.

Acceptance:

```bash
uv run --group test pytest tests/test_pack_neutrality.py -q -v
uv run --group test pytest -q
```
